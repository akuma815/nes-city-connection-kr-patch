# City Connection (Japan) 조사

- 1차 정적 조사: 2026-08-12
- 2차 실행 검증(Mesen 헤드리스): 2026-08-12

대상: `original/City Connection (Japan).nes`

사실(파일 또는 실행에서 직접 확인), 추정, 미확정을 구분해 적는다.

## 1. 카트리지 구조 — 사실

| 항목 | 값 |
| --- | --- |
| 포맷 | iNES 1.0 |
| 매퍼 | **87** (Jaleco/Konami 계열 CHR 뱅크 전환 전용) |
| PRG-ROM | 16KB × 1 |
| CHR-ROM | 8KB × 2 = 16KB (**CHR-RAM 아님**) |
| 미러링 | 세로(vertical) |
| 배터리·트레이너 | 없음 |
| 벡터 | NMI `$869E`, RESET `$8000`, IRQ `$873F` |

PRG 16KB는 `$8000-$BFFF`에 매핑되고 `$C000-$FFFF`에 미러된다. 코드는 `$8xxx-$Bxxx` 주소를 쓴다.
따라서 **PRG 오프셋 `0x0000` = CPU `$8000`**이다.

CHR 뱅크 전환은 `$6000`에 값을 쓰는 방식이고, 스토어 위치는 `$8059`, `$823F`, `$86B5`, `$A2DF` 4곳이다.
현재 뱅크는 제로페이지 `$67`에 들어 있다.

## 2. 패턴 테이블 배치 — 사실

각 8KB 뱅크는 패턴 테이블 2개다. PT0(`$0000`)과 PT1(`$1000`).
**PT0와 PT1은 서로 다른 4KB 영역이므로 같은 타일 인덱스라도 다른 그림이다.**

| | PT0 (`$0000`) | PT1 (`$1000`) |
| --- | --- | --- |
| 뱅크 0 | 자동차·플레이어 스프라이트, 숫자(`0x30-0x39`), **"CONNECTION" 타이틀 로고(`0x41-0x5F`)**, `PAUSE`(`0xB6-0xBA`) | 도시 배경 A + **본문 폰트 `0x28-0x5F`** |
| 뱅크 1 | 뱅크 0과 대부분 동일하나 `0x30-0x51`이 다른 그림, `0x52-0x5E`에 `R`~`©` 글자 | 도시 배경 B + **본문 폰트 `0x28-0x5F`** |

- PT1의 `0x28-0x5F` 56타일은 **두 뱅크에서 바이트가 완전히 동일하다.**
- PPUCTRL 섀도는 제로페이지 `$20`이다.

### 화면별 패턴 테이블 — 실행으로 확정

`$2000` 쓰기를 스캔라인과 함께 추적한 결과, **화면 분할(mid-frame 전환)은 없다.**
`$2000` 쓰기는 전부 스캔라인 246 이후(vblank)에서만 일어난다.

| 화면 | BG | 스프라이트 | 근거 |
| --- | --- | --- | --- |
| 타이틀 | **PT0** (`$88`) | PT1 | 로고·점수 숫자·`© 1985`가 BG |
| 플레이·READY·GAME OVER | **PT1** (`$90`) | PT0 | HUD와 본문이 BG |

### 타이틀 메뉴 문자는 스프라이트다 — 실행으로 확정

타이틀 화면 OAM을 덤프한 결과 `1PLAYER`, `2PLAYERS`, `JALECO`, `1P`/`TOP`/`2P`는
전부 **스프라이트**이며 PT1 폰트 타일(`$31 $50 $4C $41 $59 $45 $52` = `1PLAYER`)을 쓴다.

- 각 줄이 정확히 스프라이트 8개다. **NES의 스캔라인당 스프라이트 8개 한계에 딱 맞춰 설계돼 있다.**
- 따라서 **번역문도 한 줄 8타일을 넘길 수 없다.**
- 반대로 좋은 소식은, PT1 폰트 하나를 고치면 플레이 화면 BG 문자와 타이틀 메뉴 문자가 **함께** 바뀐다는 점이다.

## 3. 폰트 매핑 — 사실

PT1 타일 인덱스가 곧 ASCII다. 게임은 문자 코드를 변환하지 않고 타일 번호를 그대로 나열한다.

| 타일 | 내용 | 실행 중 배경 사용 |
| --- | --- | --- |
| `0x28`~`0x2C` | 빈 타일 5개 | 미관측 |
| `0x2D` | `,` | 원문 문자열 전용 |
| `0x2E` | `.`(보너스·엔딩의 마침표) | 원문 문자열 전용 |
| `0x2F` | `!` | 원문 문자열 전용 |
| `0x30`~`0x39` | `0`~`9` | **다수 — 회수 금지** |
| `0x3A` | 블록 | **205,420회 — 회수 금지** |
| `0x3B` | 블록 | **15,988회 — 회수 금지** |
| `0x3C` | 블록 | 미관측이나 형제 타일과 함께 보호 |
| `0x3D` | 블록 | **73,826회 — 회수 금지** |
| `0x3E` | 블록 | **38,534회 — 회수 금지** |
| `0x3F` | 빈 타일처럼 보이지만 **하늘 타일** | **310,866회 — 회수 금지** |
| `0x40` | 공백 | **305,362회 — 회수 금지** |
| `0x41`~`0x5A` | `A`~`Z` | 원문 문자열 전용 |
| `0x5B` | `-` | 미관측 |
| `0x5C` | `.` | **문자열 밖 사용 — 카운트다운 `2.4`의 소수점** |
| `0x5D` | `=` | 원문 문자열 전용 |
| `0x5E` | `©` | 미관측 |
| `0x5F` | 소형 기호 | 원문 문자열 전용(HUD 끝에 포함) |

`0x60`~`0xFF`와 `0x00`~`0x27`은 도시 배경 타일이며 뱅크마다 다르다.

> 1차 정적 조사에서는 `0x3F`를 "빈 타일 = 회수 후보"로 적었으나 **틀렸다.**
> ROM에서 전부 색 0이라 비어 보였을 뿐, 실제로는 하늘을 칠하는 데 쓰인다.
> 카나리아 빌드를 넣자 하늘 전체가 체커보드로 바뀌어 즉시 드러났다.

## 4. 텍스트 인벤토리 — 사실

문자열은 코드 사이에 데이터로 박혀 있다. 압축 없음, 포인터 테이블 없음, 종료자 `0xFF`, 줄바꿈 `0xFE`, 공백 `0x40`.

| CPU 주소 | 길이 | 원문 | 용도 |
| --- | ---: | --- | --- |
| `$81FB` | 9 | `GAME OVER` | 게임 오버. `$819C`가 `$21CB`에 9타일 기록 |
| `$82D6` | 6 | `READY ` | 스테이지 시작. `$82B7`이 `$2093`에 6타일 기록 |
| `$8A13` | 23 | `WARP BONUS` / `OIL✳1000` / `POINT` | 보너스. `$89D1`이 `$2214`10 / `$2254`8 / `$2279`5로 나눠 기록 |
| `$8B1A` | 32 | `1PLAYER` `2PLAYERS` `JALECO` `1P` `TOP` `2P` | 타이틀 메뉴(스프라이트로 표시) |
| `$8B42` | 6 | `© 1985` | 타이틀 저작권. `$8B0E`가 `$2349`에 6타일 |
| `$8B48` | 7 | ` PLAYER` | **간주 화면과 게임오버 화면이 공용.** `$80BD`/`$81BA` |
| `$8D94` | 118 | 타일맵 | **"CONNECTION" 로고** (PT0 뱅크0). `$8A3D` |
| `$8E0A` | 54 | `NOW,YOU HAVE DRIVEN` / `ALL THE HIGHWAY!!` / ` OIL   ✳100=` | 엔딩. **로고와 같은 루틴**을 `$8D94 + 0x76`으로 이어 읽는다 |
| `$A2BC` | 30 | `UP     00     KM OIL     _    ` | 플레이 중 HUD. `$A374` |

### HUD 칸 배치 — 정적 라벨은 3칸뿐이다

문자열은 화면 3행 2열부터 30칸이지만 대부분을 동적 필드가 덮어쓴다.

| 칸(문자열 idx) | 화면 열 | 쓰는 코드 | 내용 |
| --- | --- | --- | --- |
| — | 01 | `$A361` | 플레이어 번호 (문자열 밖) |
| **0~2** | **02~04** | — | **정적 라벨. 여기만 자유롭다** |
| 3~6 | 05~08 | `$A09E` | 점수 4자리 (선행 0은 공백) |
| 10~13 | 12~15 | `$A0BC` | 거리 4자리 |
| 20~22 | 22~24 | `$A0DA` | 연료 3자리 |
| 27 | 29 | `$A0F3` | 남은 차 1자리 |

### 1차 조사에서 틀렸던 것

| 항목 | 1차 기록 | 실제 |
| --- | --- | --- |
| `$8B42` | 13바이트 한 덩어리, 뒤 `PLAYER`는 미사용 | `$8B42`(6, 저작권) + `$8B48`(7, ` PLAYER`) 별개. 후자는 두 화면에서 쓰인다 |
| `0x2E` | 마침표 | **`✳`(×) 기호** |
| HUD 라벨 공간 | 6칸 | **3칸** |
| `$8D93`의 `0x60` | 로고 데이터 | 앞 루틴의 RTS. 로고는 `$8D94`부터 |
| `$8D93` 참조 `$82C1`/`$8572` | 포인터 | `LDA #$93` 오탐. 실제 참조는 `$8A56` |

` PLAYER` 누락은 정적 조사로는 못 잡고 **QA 스윕에서 `1 PLA인용`으로 깨진 화면**을 보고 찾았다.
같은 종류의 누락을 기계적으로 잡으려고 `audit_strings.py`를 만들었다.

정확한 바이트는 `workspace/config/rom_map.json`에 있고,
`analyze_tile_usage.py`가 전사가 아니라 **PRG 실바이트**를 읽어 사용 문자 집합을 계산한다.

**화면 텍스트 총량은 문자열 8덩이, 168바이트다. 일본어(가나·한자)는 한 글자도 없다.**

## 5. PRG 여유 공간 — 사실

같은 바이트 16회 이상 반복 구간은 총 142바이트(0.9%)뿐이고,
그중 실질 자유 공간은 `$88E0-$8902`의 35바이트와 ROM 끝 `$BFE0-$BFF9`의 26바이트, **합계 약 61바이트**다.
새 6502 루틴을 넣으려면 기존 코드를 회수해야 한다.

## 6. 스테이지 제어 변수 — 사실

`$A2DA`의 `LDX $A0 : LDA $A2B6,X : STA $6000 : STA $67`에서 시작해 다음을 확정했다.

```
$822F  E6 A0     INC $A0        ; 스테이지 진행
$8231  A5 A0     LDA $A0
$8233  C9 06     CMP #$06       ; 도시 6개
$8235  90 04     BCC +4
$8237  A9 00     LDA #$00
$8239  85 A0     STA $A0        ; 0으로 순환
$823B  E6 A1     INC $A1        ; 회차(랩) 증가
```

| 항목 | 값 |
| --- | --- |
| 스테이지 인덱스 | 제로페이지 **`$A0`** (0~5) |
| 회차(랩) | 제로페이지 `$A1` |
| 스테이지→CHR 뱅크 표 | `$A2B6` = `00 00 FF 00 FF FF` (`00`=뱅크0, `FF`=뱅크1) |
| 도시 | 0 뉴욕 · 1 런던 · 2 파리 · 3 독일 · 4 인도 · 5 일본 |
| 뱅크 1을 쓰는 스테이지 | **2, 4, 5** |

`$A0`은 `$822F`, `$8239`, `$885A` 세 곳에서만 쓰이고 나머지는 전부 읽기다. 스크래치 변수가 아니라 상태 변수다.
따라서 **프레임 경계에서 `$A0`을 강제로 쓰면 원하는 도시를 그대로 로드할 수 있다.**

```powershell
python .\workspace\scripts\run_qa.py build/canary_blank.nes --out work/qa/canary_s4 --poke A0=4
```

## 8. 미확정

1. **`PAUSE`(PT0 `0xB6-0xBA`)의 표시 경로.** 스프라이트로 추정하나 확인하지 않았다.
2. **엔딩 화면이 쓰는 뱅크·패턴 테이블.** 엔딩에 도달하지 못했다.
   다만 엔딩이 쓰는 타일은 전부 원문 문자열 안에 있어 예산에는 영향이 없다.
3. **`$8B42`의 `PLAYER`가 화면 어디에 나오는지.** 타이틀에는 `© 1985 JALECO`가 보이고 `JALECO`는 스프라이트다.
4. **회차(`$A1`)가 올라간 뒤의 화면.** 2회차 이후 배경·난이도 변화는 확인하지 않았다.
5. 미국판·유럽판과의 차이는 조사하지 않았다. 이 프로젝트는 일본판만 대상으로 한다.
