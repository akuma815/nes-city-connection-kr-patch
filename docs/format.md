# 형식 정리

## 1. ROM 레이아웃

```
0x0000-0x000F  iNES 헤더 16바이트
0x0010-0x400F  PRG-ROM 16KB   -> CPU $8000-$BFFF (그리고 $C000-$FFFF 미러)
0x4010-0x800F  CHR-ROM 16KB   -> 8KB 뱅크 2개
                 뱅크 n 오프셋 0x0000-0x0FFF = 패턴 테이블 0 (PPU $0000)
                 뱅크 n 오프셋 0x1000-0x1FFF = 패턴 테이블 1 (PPU $1000)
```

PRG 오프셋 ↔ CPU 주소: `cpu = 0x8000 + prg_offset`

## 2. 타일 형식

NES 표준 2bpp 플레이너 8×8 타일, 타일당 16바이트.

```
바이트 0~7   각 행의 비트플레인 0
바이트 8~15  각 행의 비트플레인 1
픽셀 값 = plane0 비트 | (plane1 비트 << 1)   (0~3)
```

색은 타일이 아니라 어트리뷰트 테이블이 16×16 픽셀 단위로 고르는 팔레트에 달려 있다.
본문 글자는 원본에서 값 3(가장 밝은 색) 한 가지로만 그려져 있다 —
**한글 글리프도 값 0과 값 3만 쓰면 원본과 같은 팔레트로 안전하게 표시된다.**

## 3. 문자 인코딩

별도 인코딩이 없다. 화면에 찍히는 바이트가 곧 패턴 테이블의 타일 번호다.
그 번호 배치가 ASCII와 일치해서 사람이 읽을 때만 ASCII처럼 보인다.

제어값:

| 값 | 의미 |
| --- | --- |
| `0xFE` | 줄바꿈 (다음 행) |
| `0xFF` | 문자열 종료 |
| `0x40` | 공백 |

`0xFE`/`0xFF`는 타일 번호 공간과 겹치지만, 해당 인덱스가 문자열에 쓰이지 않으므로 충돌하지 않는다.
**한글 글리프를 `0xFE`, `0xFF`에 배정하면 안 된다.**

문자열은 포인터 테이블이 아니라 코드 안의 절대 주소 참조(`LDA #<addr` / `LDA #>addr` 또는
`LDY #0 : LDA table,Y`)로 읽힌다. 확인된 참조는 `docs/survey.md` 4장 표에 있다.

## 4. 문자열 길이 규칙

문자열이 코드 사이에 끼어 있으므로 **길이를 바꾸면 뒤따르는 코드가 밀린다.**
번역 시 원칙은 다음과 같다.

- 길이를 원본과 **정확히 같게** 유지하고 남는 칸은 `0x40`(공백)으로 채운다.
- 길이를 늘려야 하면 그 문자열만 `$88E0`의 35바이트 자유 공간으로 옮기고 참조 주소를 고친다.
- 화면 좌표는 `$2006`(PPUADDR)에 미리 쓰인 값으로 정해진다. 글자 수가 줄면 시작 좌표도
  같이 옮겨 가운데 정렬을 맞출 수 있다. 확인된 PPUADDR 상수 목록은 `survey_prg.py` 출력에 있다.

## 5. 한글 배정 규칙(초안)

- 한글 1음절 = 8×8 타일 1개.
- 배정 가능 인덱스는 PT1의 `0x41-0x5A`(A~Z 회수분)를 우선 쓰고, 검증 후 `0x28-0x2C`, `0x3F`,
  `0x5B`, `0x5D`, `0x5F`를 추가한다.
- 배정표는 `workspace/font/mapping/hangul_map.json`에 둔다(아직 없음).
- **뱅크 0과 뱅크 1의 PT1 `0x28-0x5F` 영역에 같은 바이트를 써야 한다.** 한쪽만 고치면
  스테이지에 따라 글자가 깨진다.
